# SiteFlow — Papinsvet Lab Device Sync Tool

Локальный инструмент управления светом через Art-Net для Windows и macOS.

Главная функция — гибкое назначение и переадресация фейдеров DMX-пульта («расчёски») по секциям на выбранные приборы. Сопоставление по функциям (Master, RGB, White, Strobe и другим) учитывает различия в расположении каналов DMX-карт: один фейдер может управлять одинаковой функцией нескольких разных приборов. Неподдерживаемые функции пропускаются, конфликты назначений отклоняются. Произвольное преобразование диапазонов сервисных кодов разных производителей требует отдельных профилей и не выполняется автоматически.

Также доступны ручные виртуальные фейдеры с возвратом управления физическому пульту при движении соответствующего фейдера, общие профили приборов, тесты по приборам, Blackout, LED-контроллеры, монитор входящего Art-Net, журналы и поиск сетевых устройств. Интерфейс работает в браузере; облако для работы не требуется.

## Запуск

Нужен Python 3.10 или новее, сторонние Python-библиотеки не нужны.

- Windows: запустите `Start-SiteFlow.bat` двойным щелчком. При установке Python включите Add Python to PATH.
- macOS: запустите `Start-SiteFlow.command`; если файл не исполняемый, в Terminal выполните `sh Start-SiteFlow.command` из папки проекта.
- На этом компьютере откройте http://127.0.0.1:8765. С другого устройства в той же локальной сети используйте `http://<LAN-IP-компьютера>:8765`. Остановка — Ctrl+C в окне сервера.

Общий запуск: `python server.py --scan-on-start` (на macOS — `python3`).

## Сеть

Поддерживаются активные физические LAN-адаптеры Windows и интерфейсы en* macOS, включая Wi-Fi и Ethernet. Сеть должна быть частной IPv4 с маской /24–/30. Если подходящих адаптеров несколько, укажите локальный адрес нужного: `python server.py --host-ip 192.168.18.5 --scan-on-start`. На macOS используйте `python3`.

Nmap необязателен. Установленный `nmap` должен быть доступен в PATH; без него остаются ARP-наблюдения и проверки сохранённых устройств, поиск новых устройств может быть неполным. Для приёма Art-Net нужен входящий UDP 6454 в локальной сети; HTTP-интерфейс по умолчанию слушает все локальные интерфейсы. Используйте его только в доверенной локальной сети. Если UDP-порт занят другой программой, сервер покажет ошибку. Поток Art-Net необходимо направить на актуальный LAN-адрес этого компьютера.

`--port 8766` меняет HTTP-порт. `--refresh-seconds 0` отключает автоматическую проверку устройств. Настройки, карты приборов и журналы хранятся в `data/`; переносите эту папку отдельно между компьютерами при остановленном сервере. Она исключена из Git. `seed.json` содержит исходный инвентарь лаборатории; его адреса требуют проверки в вашей сети.

## Управление светом

Назначения работают по сохранённым картам функций приборов. Например, Strobe может находиться на канале 6 у одного прибора и на канале 8 у другого. Совпадение названий функций не гарантирует одинакового смысла всех значений 0–255: специальные диапазоны и сервисные команды проверяйте по документации конкретного прибора.

Активные сохранённые назначения могут отправлять ArtDmx при запуске только после подтверждения режима SOFTWARE CONTROL. **Blackout** отправляет проверенный кадр из 512 нулей на подтверждённый выходной Universe, затем останавливает TX инструмента; это не выключает другие источники или автономную маршрутизацию контроллера. Монитор показывает сетевые данные, а не измеренный физический выход DMX.

## Правила надёжности маршрутизации

- Любой DMX-адрес вычисляется от стартового адреса прибора: `start + channelIndex - 1`. Номер канала профиля — локальный для прибора; это не абсолютный канал Universe. Эти вычисления покрываются тестами для каждого типа управления.
- Ошибка цели из-за отсутствующего прибора, карты или Universe должна пропустить только эту цель. Остальные корректные цели продолжают работать; UI и статус маршрута перечисляют пропущенные ID.
- Перед сборкой выходного кадра проверяются режим контроллера, свежесть его конфигурации, направление порта, Universe, диапазон адресов и BLACKOUT. Неизвестная конфигурация блокирует отправку.
- При удалении правила/цели/ручного управления ранее занятые каналы должны быть освобождены следующим кадром. Нельзя молча оставлять последнее значение на приборе или очищать весь Universe, если запрос касался только одного прибора.
- Остановка и BLACKOUT — разные действия: BLACKOUT отправляет 512 нулей, подтверждает факт отправки, затем запрещает TX. Обычный STOP не должен сообщать об успешном погашении, если нулевой кадр не был отправлен.
- Триггеры последовательностей работают по переходу: высокий уровень запускает один раз, удержание не перезапускает; низкий уровень повторно взводит. Hold/Toggle MIDI назначаются явно и сохраняются; для Toggle два нажатия должны включать и выключать состояние.
- Данные MIDI и DMX объединяются по функции и последнему изменившемуся источнику, не по факту повторного кадра. Отсутствующий или устаревший источник не должен перетирать актуальное управление другого источника.
- FX Activate обрабатывается по изменению значения каждого источника. Неподвижные MIDI/DMX значения, включая ноль, не переигрывают активацию другого источника или ручное выключение. Изменения активации разрешаются до запуска секвенции; состояние CH1/CH2 для отправки считывается после этих изменений.
- При активном роутинге кадр включает каналы Activate и Effect всех зарегистрированных FX в выходном Universe, даже когда они выключены. Нули повторяются в последующих кадрах: один потерянный пакет выключения или сокращение длины кадра не должны оставлять FX активированным. Повторная обработка неизменных входов не должна сама будить роутер.
- Любое исправление, меняющее состояние или маршрутизацию, сопровождается регрессионным тестом для штатного случая и пограничного случая (нет цели, устаревший вход, смена Universe, выключение/сброс). Физическую выдачу DMX нельзя считать подтверждённой только по сетевому кадру.

## Проверки

`python -X utf8 -m unittest discover -v`

В `.github/workflows/tests.yml` подготовлена матрица Windows/macOS с Python 3.10, 3.12 и 3.13. Локально на Windows с Python 3.12 проходят 61 тест, включая HTTP API и UDP loopback. Ветки разбора сетевых данных обеих платформ проверяются синтетическими примерами. Реальный приём и управление светом на оборудовании macOS/Windows требуют отдельной проверки на площадке.

## Traktor MIDI template

В MIDI Monitor кнопка **Load template / Reload template** импортирует активный шаблон S2 MK2 из Controller Editor на этом Mac; при отсутствии локального файла используется снимок `profiles/traktor-s2-mk2.ncs`. В снимке 111 входных назначений: Common 43, Basic 34, Shift 34. Выходные LED-цепочки исключены из входов. Вращение джога общее для обода и пластины, нажатие — отдельный MIDI-вход.

Привязки сохраняются на Node. Перед импортом создаётся резервная копия в `data/midi-backups/`; существующие назначения функций сохраняются при совпадении MIDI-входа. Ручной Learn, удаление и Restore доступны для отдельных элементов. **Layer** переключает просматриваемую карту Basic/Shift; оба слоя принимаются и анимируются одновременно. Маршрутизация MIDI на приборы настраивается отдельно в Input Controls.

Поток MIDI опрашивается с интервалом 100 мс без перекрывающихся запросов. Полная карта передаётся только при изменении `midiRevision`; поиск элемента по входящему сообщению выполняется через индекс. Проверки импорта и чтения CoreMIDI: `python3 -m unittest test_midi_monitor test_midi_controls test_traktor_template -v`.

## MIDI Inputs и Pixel Fill

В **Input Controls → Add virtual input** доступны DMX и MIDI. MIDI-карточка открывает живую схему контроллера и секции по 16 виртуальных фейдеров: Page A — 1–8, Page B — 9–16. Для каждого фейдера выбираются MIDI-элемент и функция прибора; для секции — целевые приборы. Роли можно заполнить из профиля PAR LED, Jellyfish, Beam или LED Matrix. Относительные энкодеры накапливают значение с настраиваемым шагом; кнопки работают как Hold или Toggle. При конкуренции MIDI и расчёски за одну функцию действует последнее движение, включая ноль. Неизменные повторные кадры не перехватывают управление. Выполнение происходит на Node, независимо от открытой страницы; TX разрешён только в подтверждённом SOFTWARE CONTROL и при снятом BLACKOUT. Приём CoreMIDI реализован для macOS.

Для **Vertical LED Matrix** у целевого прибора выбирается **PAR LED** (интенсивность цвета) или **Pixel Fill** (высота заполнения). В Pixel Fill Master задаёт яркость, RGBW — заполнение от низа: 0 — пусто, 128 — примерно половина, 255 — полностью. Граничный пиксель имеет дробную яркость. Направление можно изменить в LED Controls; существующий лимит яркости сохраняется.

**Beam Control** — временное ручное управление; после него снова действует маршрутизация Input Controls. Состояние лампы больше не блокирует Shutter/Dimmer. Программная пятиминутная блокировка повторного розжига отключена. Явные команды лампы используют CH16 на 4 секунды с возвратом в ноль; повторный запуск команды недоступен до завершения текущего импульса. Автоматического повтора нет, встроенная защита прибора не обходится. Отправка команды не подтверждает физический розжиг.

Текущая локальная проверка: **103 теста**; включает MIDI-маршрутизацию, Pixel Fill, HTTP API и UDP loopback. Сохранённые назначения, локальные состояния ламп и логи находятся в исключённой из Git папке `data/`.
